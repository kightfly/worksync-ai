# Superpower · systematic-debugging（系统化调试）

## 一句话

先复现与证据，再定位根因，再最小修复；禁止靠猜修。

## 在本仓库的位置

调试类 Superpower；用于 **4p12s ⑧** 红灯/缺陷，或独立 Bug 请求。

## 触发条件

- 测试失败、行为异常、用户报 Bug
- 禁止触发词式任务：「帮我修一下」且无复现信息时，先要证据

## 必读输入

1. 失败日志、复现步骤、期望 vs 实际
2. 相关测试与最近改动
3. 设计/规格中的正确行为定义

## 任务步骤

1. **复现**：稳定复现或记录无法复现
2. **证据**：日志、断言、截图、请求/响应
3. **定位**：缩小范围（层：UI / API / 领域 / DB）
4. **根因**：一句话因果，不是症状
5. **修复**：先补失败测试（若缺）→ 最小改动 → 验证
6. 回归相关套件；回写 TASK / 缺陷记录

## 产出路径

- 失败测试（若适用）、修复 diff、证据摘要

## 门禁检查表

- [ ] 有复现或明确阻塞说明
- [ ] 根因已陈述
- [ ] 有验证证据（测试或约定检查）

## 禁止事项

- 禁止无证据多处乱改
- 禁止修表象留下根因
- 禁止用新功能掩盖 Bug
