## 1. 验证目标与范围

### 1.1 目标

用可重复证据证明本期范围已交付：

1. 认证与路由守卫（US-001～003）
2. タスク CRUD + 状态机合法/非法路径（US-010～013）
3. 打刻只读一覧与日次集計（含跨日，US-020～021）

| 层级 | 工具 | 执行步骤 |

| 单元 | Vitest（+ Testing Library 组件测） | ⑧ |

| E2E | Playwright（真浏览器 + 真 API + 真 DB） | ⑩ |
| 质量门 | ESLint / TypeScript strict | ⑧～⑪ |

### 1.3 范围外（本期不阻塞）

- NFR-001 性能压测自动化（仅抽样参考）
- 多用户隔离压测、负载测试
- 打刻写入 API（明确不做）

| 层级 | 验证什么 | 允许 Mock |
|------|----------|-----------|

| **E2E** | 浏览器主路径 + 真 API + 真 DB | **禁止** Mock 后端或 DB |

## 3. 禁 Mock 节点

| 节点 | 步骤 | 说明 |
|------|------|------|
| 集成-DB | ⑨ | 真实 PostgreSQL（`DATABASE_URL`）；跑 migration + seed |
| 集成-HTTP | ⑨ | 真实 Fastify inject 或本地端口；非全 Mock handler |
| E2E-全链路 | ⑩ | Playwright → 真前端 → 真后端 → 真 DB |
| Domain 状态机结论 | ⑧⑨ | 非法迁移必须由 Domain 拒绝；禁止仅前端隐藏按钮当完成 |

**允许 Mock（仅单元）**：

- HTTP client 外围（测组件 loading 态时可 MSW，但**不得**作为 ⑨⑩ 证据）
- 时钟（时区单测可用 fake timers，须声明「Tokyo 墙钟」输入）

**假完成定义（禁止）**：

- 仅单测绿灯宣称功能完成
- ⑨/⑩ 全 Mock DB 或 API 却写「真实链路通过」

## 5. 失败归因规则

连续失败时按序判定：

1. **测试用例错误**（断言与契约/AC 不符、选择器过脆）
2. **设计/契约错误**（design 与实现意图冲突 → 回⑤改契约并同步故事）
3. **实现策略错误**（代码 bug）

**⑧ 纪律**：同一 TASK **连续 5 次红灯** → 停止并升级给人（`tdd.mdc` / AGENTS）。

证据要求：失败日志或报告路径回写 TASK / `verification-result.md`；不得只靠聊天宣称通过。
