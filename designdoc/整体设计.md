## 1. 产品定位与范围

### 1.1 定位

日文界面的「勤怠・タスク管理」迷你后台，用于练习 **AI Agent 在约束下按 4p12s 可靠交付**。

### 1.2 本期做

- 用户认证（登录 / 登出）与受保护路由
- タスク CRUD 与**状态机**（BR-007～009）
- 打刻：**一覧**与**日次集計**（只读；数据由 seed 初始化，BR-010）
- UTC 存储 / Asia/Tokyo 展示
- 质量门禁：单测 → 集成 → E2E → Git → 部署证据

### 1.3 本期明确不做

- 出勤/退勤 UI 与 `POST /api/attendance`
- 多租户、SSO、审批流
- 擅自更换下方固定技术栈

## 2. 固定技术栈（实现时必须按此脚手架）

> **说明**：本分支初始**不预留** `apps/` 空壳；⑧ 执行开发时再按本表创建 monorepo。

| 层 | 技术 | 版本/说明 |
|----|------|----------|
| 前端 | React 19 + TypeScript + Vite + React Router | 固定 |
| UI | 自研样式可接受；表单用 react-hook-form + zod | 日文校验文案 |
| 后端 | Node.js + TypeScript + Fastify | 固定 |
| DB | PostgreSQL + Drizzle ORM | 真实库（如 Supabase） |
| 测试 | Vitest + Testing Library + Playwright (E2E) | E2E 为交付门禁 |
| 质量 | ESLint + Prettier + TypeScript strict | CI 含 lint/typecheck/test/e2e |
| 认证 | JWT + bcrypt（`SALT_ROUNDS=10`） | 密码 ≥ 6 字符 |

### 2.1 仓库目标结构（⑧ 落地时创建）

```
apps/web/          # React + Vite
apps/api/          # Fastify
packages/domain/   # 纯领域（User / Task）
packages/infrastructure/  # Drizzle / Repository / seed
designdoc/         # 规格与交付状态
.gientech/         # wiki / skills / rules
```

### 2.2 模块边界

1. UI → 仅调 API（不直连 DB）
2. API / Application → Domain + Infrastructure
3. Domain → 无外部依赖
4. Infrastructure → 实现 Repository，封装 Drizzle

## 4. 业务规则

### 4.1 认证

| ID | 规则 |
|----|------|
| BR-001 | 邮箱必填且格式有效 |
| BR-002 | 密码长度 ≥ 6 |
| BR-006 | UI・错误提示为日文 |

- 登录失败统一：「メールアドレスまたはパスワードが正しくありません」
- 未认证访问 `/api/*`（除 login / health）→ 401

### 4.2 タスク状态机

| ID | 规则 |
|----|------|
| BR-003 | タイトル必須 |
| BR-007 | 状态：`todo` / `in_progress` / `done`；新建默认 `todo` |
| BR-008 | 允许：`todo`→`in_progress`；`in_progress`→`done`；`in_progress`→`todo` |
| BR-009 | 禁止：`todo`→`done`；`done`→任意；违反 → 400 `INVALID_STATE_TRANSITION` +「無効な状態遷移です」 |

```
todo ──→ in_progress ──→ done
  ↑            │
  └────────────┘
```

领域层 `Task.transitionTo` 强制执行；`done` 任务本期禁止状态与内容 PATCH。

### 4.3 打刻（只读）

| ID | 规则 |
|----|------|
| BR-004 | 展示 Asia/Tokyo |
| BR-005 | DB 存 UTC |
| BR-010 | 只读；seed 初始化；无用户打刻录入 API |

跨日工时：`work_date` = 出勤时 Tokyo 日历日。

## 6. 数据模型与 API 契约摘要

### 6.1 表

- **users**：id, email(unique), password_hash, name, is_active, created_at, updated_at
- **tasks**：id, user_id(FK), title, description, status, due_date, created_at, updated_at（索引 user_id / status）
- **attendance_records**：id, user_id(FK), check_in_time, check_out_time, work_date, created_at

### 6.2 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/health` | 健康检查 |
| POST | `/api/auth/login` | 登录 → user + token |
| POST | `/api/auth/logout` | 登出（可无状态） |
| GET/POST | `/api/tasks` | 一覧 / 作成 |
| PATCH/DELETE | `/api/tasks/:id` | 更新 / 削除 |
| GET | `/api/attendance` | 一覧（query: startDate, endDate） |
| GET | `/api/attendance/statistics` | 日次集計 |

时间输出：ISO 8601 带 Tokyo 偏移（如 `+09:00`）。
