## 概述

AI Harness 目标包含三个核心实体：User、Task、AttendanceRecord。数据使用 PostgreSQL 存储，通过 Drizzle ORM 访问；Schema 规划路径为 **`packages/infrastructure/db/schema.ts`**（与 `AGENTS.md` 分层一致）。

## 业务规则

### 用户（User）

- 邮箱唯一
- 密码以 bcrypt 哈希存储（`SALT_ROUNDS = 10`，见 `design.md`）
- 支持软删除（`is_active = false`）
- `name` 可选（nullable）

### 任务（Task）

- 用户只能操作自己的任务（`user_id` 过滤）
- 状态流转：`todo` → `in_progress` → `done`（允许 `in_progress` → `todo` 回退）
- `due_date` 为 **DATE** 类型（非 TIMESTAMP）
- `title` 最长 255 字符

### 打卡记录（AttendanceRecord）

- 每日每用户只能有一条出勤记录（按 `work_date`）
- `check_in_time` 必填；`check_out_time` 可空（未退勤）
- 时间戳以 UTC 存储；`work_date` 按出勤时的 Asia/Tokyo 日期计算
- 工时 = `check_out_time` - `check_in_time`

## 数据访问模式（规划）

所有数据访问通过 Repository 层封装，使用 Drizzle ORM：

```typescript
// 查询示例（实现后）
const user = await db.select().from(users).where(eq(users.email, email))
const userTasks = await db.select().from(tasks).where(eq(tasks.userId, userId))
```

详见 [Repository 层](../基础设施与中间件/Repository层.md)（📋 未落地）。

## 时区规则

| 字段 | 存储格式 | 展示格式 |
|------|---------|---------|
| `check_in_time` | UTC TIMESTAMP | Asia/Tokyo |
| `check_out_time` | UTC TIMESTAMP | Asia/Tokyo |
| `work_date` | DATE（Asia/Tokyo 日） | Asia/Tokyo |
| `created_at` | UTC TIMESTAMP | 一般不展示 |
| `updated_at` | UTC TIMESTAMP（仅 users、tasks） | 一般不展示 |

> 注意：`attendance_records` 表没有 `updated_at` 字段，只有 `created_at`。

详见 [编码指引](../编码指引.md) 时区规则章节与 `.gientech/rules/timezone.mdc`。
