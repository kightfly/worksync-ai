## 重要说明

本文档描述 **目标 Service 层** 职责与流程。**当前仓库不存在** `apps/api/src/services/` 或 `packages/application/` 下任何 Service 实现。

| 规划路径 | 现状 |
|----------|------|
| `packages/application/`（Auth / Task / Attendance Service） | 📋 |
| `packages/domain/`（实体与领域规则） | 📋 |
| `apps/api/src/routes/`（调用 Service） | 📋 |

`design.md` 将应用层置于 **Application Layer**；实现 TASK 时以 `packages/application` 为准，路由层仅做 HTTP 适配。

## 架构位置（目标）

```
路由（Route） → Service → Repository → Drizzle ORM → PostgreSQL
                  ↑
              领域逻辑（Domain）
```

**当前**：无路由链、无 Service、无 Repository。

Service 层是 **事务边界**，不依赖 UI；UI 通过 API 间接调用（见 `AGENTS.md` 模块边界）。

## 规划 Service

### AuthService

负责用户认证逻辑（`design.md`：`login`、`logout`、`getCurrentUser`）。

| 方法 | 说明 |
|------|------|
| `login(email, password)` | 验证邮箱密码，返回 JWT 与用户信息 |
| `logout()` | 无状态登出（客户端清除 Token；服务端可选黑名单 🔮） |
| `getCurrentUser(userId)` | 按 Token 中的用户 ID 加载当前用户 |
| `verifyToken(token)` | 内部：解析并校验 JWT |

#### 认证流程（规划）

```
1. 客户端 POST /api/auth/login { email, password }
2. AuthService.login()
   a. UserRepository.findByEmail(email)
   b. bcrypt.compare(password, user.passwordHash)
   c. 验证 is_active
   d. jwt.sign({ userId, email }, JWT_SECRET, { expiresIn: '24h' })
3. 返回 { token, user }
```

#### 安全规则

- 密码使用 bcrypt，`SALT_ROUNDS = 10`（`design.md`）
- 产品规则：密码最少 **6 字符**（`prd.md` BR-002）
- JWT 有效期 24h；Payload 最小化 `{ userId, email }`
- 登录失败统一日文提示，不透露邮箱是否存在
- `jsonwebtoken`、`bcrypt`：**📋 尚未安装**（见 [技术栈与依赖](../技术栈与依赖.md)）

### TaskService

负责任务 CRUD 与状态流转。

| 方法 | 说明 |
|------|------|
| `getTasks(userId, filters?)` | 获取用户任务列表 |
| `getTaskById(userId, taskId)` | 获取任务详情（校验归属） |
| `createTask(userId, data)` | 创建任务 |
| `updateTask(userId, taskId, data)` | 更新任务（含 PATCH 状态） |
| `deleteTask(userId, taskId)` | 删除任务 |

#### 状态流转验证

```typescript
const VALID_TRANSITIONS: Record<string, string[]> = {
  todo: ['in_progress'],
  in_progress: ['done', 'todo'],
  done: [],
};

function canTransition(from: string, to: string): boolean {
  return VALID_TRANSITIONS[from]?.includes(to) ?? false;
}
```

#### 用户隔离

所有方法接收 `userId`，Repository 查询带 `user_id` 条件；`getTaskById` / `update` / `delete` 须校验记录归属。

### AttendanceService

`design.md` 列出：`list`、`statistics`。打刻（出勤/退勤）来自用户故事，与 [打卡 API](../API参考/打卡API.md) 的 `POST /api/attendance` 对应，实现 TASK 须回写 `design.md`。

| 方法 | 说明 |
|------|------|
| `checkIn(userId)` | 出勤打卡（📋 用户故事扩展） |
| `checkOut(userId)` | 退勤打卡（📋 用户故事扩展） |
| `getRecords(userId, startDate?, endDate?)` | 获取打卡记录列表 |
| `getStatistics(userId, startDate, endDate)` | 按日工时统计 |

#### 出勤逻辑（规划）

```
1. 获取当前 UTC 时间
2. 转换为 Asia/Tokyo 日期作为 work_date
3. 检查该用户该 work_date 是否已有记录
4. 如无记录，创建并设置 check_in_time
5. 如已有记录，返回冲突错误
```

#### 退勤逻辑（规划）

```
1. 获取当前 UTC 时间
2. 查找用户当天出勤记录
3. 如无记录或已退勤，返回错误
4. 设置 check_out_time
```

#### 工时计算

```typescript
function calculateWorkHours(checkIn: Date, checkOut: Date): number {
  return (checkOut.getTime() - checkIn.getTime()) / 3600_000;
}
```


## 错误处理（规划）

Service 抛出领域错误，由 [中间件](../基础设施与中间件/中间件.md) 全局处理器转为 HTTP 响应：

| 场景 | 抛出错误 | HTTP | 错误代码 |
|------|---------|------|----------|
| 用户不存在 | `NotFoundError` | 404 | `NOT_FOUND` |
| 密码错误 | `UnauthorizedError` | 401 | `INVALID_CREDENTIALS` |
| 重复出勤 | `ConflictError` | 409 | `ALREADY_CLOCKED_IN` |
| 未出勤就退勤 | `ConflictError` | 409 | `NOT_CLOCKED_IN` |
| 无效状态转换 | `ValidationError` | 400 | `VALIDATION_ERROR` |
| 请求频率超限 | — | 429 | `RATE_LIMIT_EXCEEDED` |
