## 模块边界

### 严格分层规则（目标，与 AGENTS.md 一致）

| 层 | 目录 | 依赖规则 |
|----|------|----------|
| UI 层 | `apps/web/` | 只依赖应用服务接口；不直接访问数据层 |
| 应用服务层 | `packages/application/` | 编排领域与基础设施；事务边界；不依赖 UI |
| 领域层 | `packages/domain/` | 纯业务逻辑；无外部依赖；可独立测试 |
| 数据访问层 | `packages/infrastructure/` | Repository；Drizzle/PostgreSQL；禁 N+1 |

**依赖方向**：UI → Application → Domain ← Infrastructure

### 过渡期约定

在 `packages/` 落地前，可临时在 `apps/api/src/` 按 routes → services → repositories 组织，但 Wiki 与 TASK 须标注 **📋 待迁移至 packages/**，避免与目标架构长期偏离。

## 核心模块（设计契约 📋）

### 认证模块

- **路由（设计）**：`POST /api/auth/login`、`POST /api/auth/logout`
- **机制**：JWT 无状态，HS256
- **密码规则**：最少 **6 字符**（PRD BR-002；与登记表一致）
- 详见 [认证 API](API参考/认证API.md)

### 任务模块

- **路由（设计）**：`/api/tasks` CRUD
- **状态**：`todo` → `in_progress` → `done`
- 详见 [任务 API](API参考/任务API.md)

### 打卡模块

- **路由（设计）**：`/api/attendance`
- **时区**：DB UTC，展示 Asia/Tokyo（`.cursor/rules/timezone.mdc`）
- 详见 [打卡 API](API参考/打卡API.md)

## 数据流

### 当前可运行链路（🟡）

```
浏览器 → Vite (5173) → 静态/React 登录占位页
curl   → Fastify (3000) → GET /health
```

### 目标业务链路（📋）

```
浏览器 → Vite → Fastify 路由 → Service → Repository → PostgreSQL
```

### 认证流程（设计 📋）

```
1. POST /api/auth/login { email, password }
2. AuthService 验证 → 签发 JWT
3. 客户端 Authorization: Bearer <token>
4. 中间件验证 → 业务路由
```
