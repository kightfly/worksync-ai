## 概述

本文档定义了 **AI Harness - 勤怠・タスク管理** 项目的编码规范和最佳实践，旨在确保代码质量、可维护性和团队协作效率。所有开发人员必须严格遵循本规范，通过代码审查和自动化工具确保规范的执行。

### 核心原则
- **可读性优先**: 代码应该易于理解和维护
- **一致性**: 保持代码风格和结构的一致性
- **简洁性**: 避免过度复杂的设计和实现
- **安全性**: 遵循安全编码最佳实践
- **性能**: 在保证可读性的前提下优化性能

### 项目背景
- **项目名称**: AI Harness - 勤怠・タスク管理
- **项目定位**: 一个日文界面的「勤怠・タスク管理」迷你后台系统，用于练习 AI Agent 在约束下的可靠交付能力
- **开发模式**: TDD（测试驱动开发）— 来源：[AGENTS.md](../../AGENTS.md)

## 代码风格规范

### 基本格式规范

#### 缩进和空格
- 使用 **2 个空格** 进行缩进（TypeScript/JavaScript 社区标准）
- 行尾不允许有空格
- 文件末尾保留一个空行
- 每行代码长度不超过 **120 个字符**

#### 大括号规范
```typescript
// ✅ 推荐：大括号不换行
export function createUser(data: UserData) {
  if (!data.email) {
    throw new ValidationError('Email is required');
  }
}

// ❌ 不推荐：大括号换行
export function createUser(data: UserData)
{
  if (!data.email)
  {
    throw new ValidationError('Email is required');
  }
}
```

#### 空行规范
- 类成员之间使用一个空行分隔
- 函数之间使用一个空行分隔
- 逻辑块之间使用空行提高可读性
- 导入语句分组，组间使用空行分隔

### 导入语句规范

```typescript
// 1. 第三方库
```

## 命名规范

### 类/组件命名规范

#### 类名、接口名、类型名
- 使用 **PascalCase**（首字母大写的驼峰命名）
- 类名应该是名词，具有描述性
- 避免缩写，除非是广泛认知的缩写

```typescript
// ✅ 推荐
export class UserService { }
export interface UserProps { }
export type TaskStatus = 'todo' | 'in_progress' | 'done';

// ❌ 不推荐
export class usrSvc { }
export interface user_props { }
```

#### React 组件命名
```tsx
// ✅ 推荐：PascalCase
export function LoginForm() { }
export const TaskItem = () => { };

// ❌ 不推荐
export function loginForm() { }
```

#### 接口实现类命名
```typescript
// ✅ 推荐：实现类添加 Impl 后缀
export interface UserRepository {
  findById(id: string): Promise<User | null>;
}

export class UserRepositoryImpl implements UserRepository {
  async findById(id: string): Promise<User | null> {
    // 实现
  }
}
```

### 函数命名规范

#### 函数名
- 使用 **camelCase**（首字母小写的驼峰命名）
- 函数名应该是动词或动词短语
- 布尔方法使用 `is`、`has`、`can` 等前缀

```typescript
// ✅ 推荐
export function createUser(user: User): Promise<User> { }
export function findUsersByRole(role: string): Promise<User[]> { }
export function isValidEmail(email: string): boolean { }
export function hasPermission(user: User, permission: string): boolean { }

// ❌ 不推荐
export function userCreate(user: User): Promise<User> { }
export function getUsers(role: string): Promise<User[]> { }
export function checkEmail(email: string): boolean { }
```

### 变量命名规范

#### 变量名
- 使用 **camelCase**
- 变量名应该具有描述性
- 避免使用单字母变量名（除了循环变量）

```typescript
// ✅ 推荐

const pendingOrders: Order[] = [];
const maxRetryCount = 3;

// ❌ 不推荐
const u = 'john';
const list: Order[] = [];
const n = 3;
```

#### 常量命名
- 使用 **UPPER_SNAKE_CASE**
- 常量名应该具有描述性

```typescript
// ✅ 推荐
export const DEFAULT_USER_ROLE = 'USER';
export const MAX_LOGIN_ATTEMPTS = 3;
export const API_VERSION = 'v1';

// ❌ 不推荐
export const defaultRole = 'USER';
export const maxAttempts = 3;
```

- 注释应该与代码同步更新

### 异常处理最佳实践

#### 异常捕获和处理
```typescript
// ✅ 推荐：具体异常处理
try {
  await userService.createUser(user);
} catch (error) {
  if (error instanceof DuplicateUserException) {
    logger.warn('User already exists: {}', user.email);
    return ResponseEntity.badRequest().body('User already exists');
  }
  if (error instanceof InvalidEmailException) {
    logger.error('Invalid email format: {}', user.email);
    return ResponseEntity.badRequest().body('Invalid email format');
  }
  throw error;
}

// ❌ 不推荐：捕获通用异常
try {
  await userService.createUser(user);
} catch (error) {
  // 处理所有异常，难以调试
}
```

#### 资源管理
```typescript
// ✅ 推荐：使用 try-with-resources 模式（TypeScript 使用 finally）
let connection: Connection | null = null;
try {
  connection = await dataSource.getConnection();
  // 使用连接
} catch (error) {
  logger.error('Database error', error);
  throw error;
} finally {
  if (connection) {
    await connection.close();
  }
}
```

## 日志规范

### 日志级别使用

#### 日志级别定义
- **ERROR**: 系统错误，需要立即处理
- **WARN**: 警告信息，可能影响系统功能
- **INFO**: 重要的业务流程信息
- **DEBUG**: 调试信息，仅在开发环境使用
- **TRACE**: 详细的跟踪信息

```typescript
// ✅ 推荐：合理使用日志级别
export async function processOrder(order: Order): Promise<void> {
  logger.info(`Processing order: ${order.id}`);

  try {
    validateOrder(order);
    calculateTotal(order);

    logger.info(`Order processed successfully: ${order.id}`);
  } catch (error) {
    if (error instanceof ValidationException) {
      logger.warn(`Order validation failed: ${error.message}`);
      throw error;
    }
    logger.error(`Unexpected error processing order: ${order.id}`, error);
    throw new OrderProcessingException('Failed to process order', error);
  }
}
```

### 日志格式规范

#### 日志消息格式
- 使用结构化日志格式
- 包含必要的上下文信息
- 避免敏感信息泄露

```typescript
// ✅ 推荐：结构化日志
logger.info(`User login successful - userId: ${userId}, ip: ${clientIp}, timestamp: ${new Date().toISOString()}`);

// ✅ 推荐：包含业务上下文
logger.warn(`Payment failed - orderId: ${orderId}, amount: ${amount}, reason: ${failureReason}`);

// ❌ 不推荐：缺少上下文信息
logger.info('Login successful');
logger.warn('Payment failed');
```

#### 日志安全
```typescript
// ✅ 推荐：避免记录敏感信息
logger.info(`User login successful - userId: ${userId}`); // 不记录密码

// ❌ 不推荐：记录敏感信息
logger.info(`User login - username: ${username}, password: ${password}`); // 安全风险
```

### TDD 强制规则

1. **先写测试，后写实现**
   - 禁止在无测试的情况下实现功能
   - 测试失败后才能开始实现

2. **测试覆盖所有业务逻辑**
   - 领域层：100% 覆盖
   - 应用层：90%+ 覆盖
   - API 层：85%+ 覆盖
   - 页面层：80%+ 覆盖

3. **测试必须独立**
   - 测试之间不可互相依赖
   - 每个测试可独立运行

4. **边界条件测试**
   - 必须测试边界值（如密码长度 5/6/100）
   - 必须测试空值、null、空数组等边界情况

5. **错误路径测试**
   - 必须测试必填项缺失
   - 必须测试格式错误
   - 必须测试权限不足场景

## 性能优化规范

### 集合使用规范

#### 集合初始化

```typescript
const list: string[] = new Array(expectedSize);
```

```typescript
// ✅ 推荐：使用数组 join
```

### 数据库操作规范

#### 查询优化
```typescript
// ✅ 推荐：使用分页查询
const users = await userRepository.findByStatus(status, {
  page: 1,
  limit: 20,
});

// ✅ 推荐：避免 N+1 查询问题

```

## 安全编码规范

### 输入验证

#### 参数验证
```typescript
// ✅ 推荐：使用 Zod 进行验证
import { z } from 'zod';

const UserCreateSchema = z.object({
  username: z
    .string()
    .min(3, '用户名长度必须在 3 个字符以上')
    .max(20, '用户名长度不能超过 20 个字符'),
  email: z.string().email('邮箱格式不正确'),
});

export function validateUserCreate(data: unknown) {
  return UserCreateSchema.parse(data);
}

// ✅ 推荐：手动验证
export function validateUser(user: User): void {
  if (!user) {
    throw new IllegalArgumentException('用户对象不能为 null');
  }
  if (!user.username?.trim()) {
    throw new IllegalArgumentException('用户名不能为空');
  }
}
```

### 敏感信息处理

#### 密码处理
```typescript
// ✅ 推荐：使用 bcrypt 加密密码
import bcrypt from 'bcrypt';

export class PasswordService {
  private readonly saltRounds = 10;

  async encodePassword(rawPassword: string): Promise<string> {
    return bcrypt.hash(rawPassword, this.saltRounds);
  }

  async matches(rawPassword: string, encodedPassword: string): Promise<boolean> {
    return bcrypt.compare(rawPassword, encodedPassword);
  }
}

// ❌ 不推荐：明文存储密码
user.setPassword('plaintextpassword'); // 安全风险
```

- [ ] 异常情况是否得到适当处理
- [ ] 性能是否满足要求

#### 代码质量检查
- [ ] 代码是否遵循命名规范
- [ ] 代码结构是否清晰合理
- [ ] 注释是否充分且准确
- [ ] 是否存在代码重复

#### 安全性检查
- [ ] 输入验证是否充分
- [ ] 敏感信息是否得到保护
- [ ] 是否存在安全漏洞
- [ ] 权限控制是否正确

### 审查流程

#### 审查步骤
1. **自检**: 开发者完成代码自检

3. **同行审查**: 至少一名同事进行代码审查
4. **修改完善**: 根据审查意见修改代码
5. **最终确认**: 审查者确认修改结果
